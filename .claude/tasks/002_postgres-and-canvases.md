## The goal

The API reads and writes Postgres as the `app` role, under RLS, through the
full layer stack: `openapi.yaml` → generated handler interface → service →
sqlc store. Three endpoints prove it: create a canvas, list canvases, read a
board. No login yet — a dev space stands in until Step 5.

## Decisions for this step

1. **Go 1.27 through the toolchain directive, not an install.** `go.mod`
   declares `go 1.27`, and the local `go` (1.23, `GOTOOLCHAIN=auto`) downloads
   the 1.27 toolchain into `~/go/pkg/mod` on first use. No system change, no
   sudo, nothing outside the module cache. Dockerfile moves to `golang:1.27-alpine`.
2. **Tools run pinned with `go run pkg@version`** from the `Makefile`, so
   nothing is installed globally and CI uses the same versions.
3. **Only the tables this step uses.** `spaces`, `canvases`, `canvas_pixels`.
   `users` and `space_members` arrive with login (Step 5), `pixels` with
   placing (Step 6). One focused migration per change, as in tea-pos.
   `canvases.created_by` is added in Step 5 (a nullable add is backward-compatible).
4. **The `app` role is created by a migration, its password is not.**
   Passwords never go in git. A migration creates `app` with `NOLOGIN` and its
   grants; `make db-app-password` then sets `LOGIN PASSWORD` from
   `APP_DB_PASSWORD` in `.env`.
5. **The dev space is seeded by a script, not a migration.** `make db-seed-dev`
   inserts one space and prints its id for `DEV_SPACE_ID`. A migration would
   put a fake tenant into every future database.
6. **Tenant scoping lives in one helper.** `service.inTenant(ctx, spaceID, fn)`
   opens a transaction, runs `set_config('app.tenant_id', $1, true)` (the
   `SET LOCAL` form), and hands `fn` a store bound to that transaction. Every
   space-scoped service call goes through it.
7. **Strict server from oapi-codegen.** Handlers get typed requests and return
   typed responses, so a response that drifts from `openapi.yaml` fails to
   compile.
8. **Board is raw bytes.** `GET /canvases/{id}/board` returns 65,536 bytes of
   `application/octet-stream`, one palette index per cell, 0 for unpainted.
9. **Tests that need a database use a separate one.** `rail_canvas_test` on the
   same server, reached through `TEST_DATABASE_URL`. Tests skip when it is
   unset, so `make check` still runs without it. CI gets its own Postgres in
   Step 7.

## Migrations

| # | File (generated by `make migrate-new`) | Contents |
| --- | --- | --- |
| 1 | `…_create_app_role.sql` | `app` role (`NOLOGIN`, not superuser), `USAGE` on schema `public`, default privileges for tables and sequences created by `postgres` |
| 2 | `…_create_spaces.sql` | `spaces (id uuid, name, slug unique, created_at)`. No RLS |
| 3 | `…_create_current_tenant_id.sql` | `current_tenant_id()`: `NULLIF(current_setting('app.tenant_id', true), '')::uuid`. NULLIF because after a `SET LOCAL` ends the setting reads `''`, and `''::uuid` would error instead of matching nothing |
| 4 | `…_create_canvases.sql` | `canvases` and `canvas_pixels`, each with `space_id`, `ENABLE` + `FORCE ROW LEVEL SECURITY`, one policy against `current_tenant_id()`. `canvas_pixels` references `canvases (id, space_id)` so its copied `space_id` cannot drift |

`canvas_pixels.pixel_id` gets its foreign key to `pixels` in Step 6.

## Files

```
api/
├── go.mod                        # go 1.27, pgx, oapi-codegen runtime
├── openapi.yaml                  # 3 endpoints + /health + error schema
├── oapi-codegen.yaml, sqlc.yaml  # generator config
├── db/migrations/                # the 4 above
├── db/queries/canvases.sql       # sqlc input
├── db/seed/dev_space.sql
└── internal/
    ├── apigen/                   # generated
    ├── store/                    # generated
    ├── platform/postgres.go      # pgx pool, max 10 connections
    ├── service/
    │   ├── tenant.go             # inTenant
    │   ├── palette.go            # palettes defined in Go
    │   └── canvases.go
    ├── handler/server.go         # implements the strict interface
    └── middleware/space.go       # DEV_SPACE_ID into the context; deleted in Step 5
```

`/health` stays dependency-free. A database failure at boot still stops the
process (fail fast), so a deploy with a bad `DATABASE_URL` never goes green.

## Order of work

1. Go 1.27 toolchain, dependencies, generators wired — **no database touched**
2. Migrations, queries, services, handlers, tests written — **no database touched**
3. **Ask the owner**, then run the migrations against Railway, set the `app`
   password, seed the dev space, create `rail_canvas_test`, run the tests
4. Owner sets three Railway variables on the `api` service (exact values given
   at that point): `APP_DB_PASSWORD`, `DATABASE_URL` (as `app`, through
   `postgres.railway.internal`, built from variable references) and `DEV_SPACE_ID`
5. Push, deploy, and check the live endpoints with `curl`

## Found while building

- sqlc singularised `canvases` to `Canvase`; fixed with a `rename` in `sqlc.yaml`
- oapi-codegen gave a shared `components/responses` error two different Go
  shapes; the spec inlines it per response through a YAML anchor instead
- `go run tool@version` picks the tool's own minimum Go; the `Makefile`
  exports `GOTOOLCHAIN=go1.27.1` so everything uses one toolchain

## How we know it works

- `make check` green, generated code up to date
- Integration tests against `rail_canvas_test`:
  - create, list and board round-trip
  - **RLS test:** as `app`, a query with no tenant set sees zero rows; with
    another space's id it sees zero rows; with the right id it sees them
  - a board for a canvas in another space is a 404, not an empty board
- Live: `POST /canvases`, `GET /canvases`, `GET /canvases/{id}/board` (65,536 bytes)
- Railway's canvas draws a line from `api` to `Postgres` once the variable
  references exist
